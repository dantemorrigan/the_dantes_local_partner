# Handoff / статус работы

Живой файл для того, кто продолжит работу (человек или ИИ). Обновлять при каждом коммите.

## Окружение
- Java 25 (в облачной сессии: `/opt/jdk/jdk-25.0.5+8`), Gradle wrapper 9.8.2, Loom 1.19, MC 26.1.2 (без обфускации, имена Mojang).
- Исходники MC для справки: `./gradlew genSources` или распаковать `*-sources.jar` из `.gradle/loom-cache`.
- Совместимость: собрать The Dante's Infinity и положить jar в `libs/` (в git не попадает). Репозиторий Infinity **не менять**.
- Тест: `LIBGL_ALWAYS_SOFTWARE=true xvfb-run -a ./gradlew runClientGameTest` → скриншоты в `build/run/clientGameTest/screenshots/`.
  Сценарий: `src/gametest/java/.../PartnerTest.java` (язык клиента ru_ru, суперплоский мир).

## Сохранность рюкзака (критический баг от пользователя)
- [x] `PersistenceTest` (`-PonlyTest=PersistenceTest`): выход/вход ×2, нокаут и возрождение, закрытие мира при дальней прогулке — всё сохраняется.
- Меры: рюкзак не выпадает при гибели напарника; снимок в запись каждые 5 с и перед каждым сохранением (`BEFORE_SAVE`); явная запись при `SERVER_STOPPING`; дальний напарник дозагружается по последним координатам; лишний «старый» напарник не удаляется, пока менеджер не загрузил записи; резервная копия больше не берётся в первый тик (пустой рюкзак).
- Если баг повторится: смотреть строки `LocalPartner` в `logs/latest.log` («Partner record…», «Restoring…», «is gone…»).

## Хотфикс сохранности (сессия 5)
- Выход из мира: напарник теперь ОСТАЁТСЯ в мире и сохраняется вместе с чанком, как обычный моб (`PartnerManager.leave`); запись хранит только свежую резервную копию (каждые 5 с, перед сохранением, при выходе) и координаты. Стеш остался только для смены измерения, ожидания вне сюжетных измерений и нокаута.
- Перед записью/переносом текущая работа сворачивается (`PartnerBrain.suspend`): поставленный верстак возвращается в рюкзак.
- Тесты: `PersistenceTest`, `WorkPersistenceTest` (после реальной работы), `ItemRoundTripTest` (все предметы игры проходят сохранение/загрузку) — зелёные. Клиент видит напарника после перезахода.
- ОТКРЫТО: если напарник ушёл далеко и мир закрыли, его сущность по сохранённым координатам не находится (чанк подгружается, но он не появляется за 20 с) — срабатывает резервная копия (≤5 с давности), данные целы. Стоит разобраться (возможно, асинхронная загрузка сущностей или не та позиция).
- ОТКРЫТО: один раз из четырёх прогонов `PersistenceTest` упал сервер (`NPE` в `ChunkMap.tick` при выходе из мира, перебор `entityMap`); повторить не удалось. Стек вне нашего кода; вероятно, структурное изменение отслеживаемых сущностей внутри цикла.
- Корень пользовательского бага «после перезахода пропадают вещи и развитие» воспроизвести не удалось; если повторится — нужны строки `LocalPartner` из `logs/latest.log`.
